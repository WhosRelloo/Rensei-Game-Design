# Hostages Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. Every implementer gets the **Global Constraints**, the **Facts** and the **Audit rulings** below together with its own task.

**Goal:** the owner's Backlog item 2, "Hostages" (player on player). When this plan is done:
- next to a knocked player, or behind a player who hasn't seen you, the existing prompt art offers **N: Take hostage / Grab**. N stays the takedown key: an enemy target means a takedown, a player target means a hostage;
- the server checks every gate (PvP only, safe zones, levels, range, rear arc for a grab, a clear line, both sides free, cooldown and grab immunity) and **never accepts an NPC as a hostage**. No takedown path ever accepts a player;
- the hostage is welded in front of the captor and led at walk speed 12. The captor's client owns the pair and the server polices it (a lead clamp, a pair check, a teleport break). The hostage's own client can't move, jump, fight, cast or draw;
- the hostage gets free by a struggle, a rescue (a hit on the captor from behind or the side, a parried light attack, the captor knocked), a time limit (180 s, halved per re-take within 10 minutes), or the captor's choice;
- the captor menu (N again, on the emote wheel's art) offers Release, Finish (the existing Grip), Demand ransom and Turn in;
- human shield: front hits on the captor land on the hostage, and NPCs hold their attack in front of a shield;
- the eight new deeds go through the existing Morality → Witness → Heat → Rumour path;
- the ransom moves money between two loaded saves in one server step, capped, with no new save fields;
- the roads, the train and the papers check refuse a pair. **Journeys with a hostage are a follow-up plan** (ruling R5 below).

Both Ye and Foundry get the same code. Nothing is published.

**Architecture:** five stages.
1. **Parity and survey** (Task 1): every script this plan touches is a manifest pair, equal to Studio in both places. A read-only survey and one Play session answer the ownership and test-seam questions.
2. **Pure rules, data, slots and seams** (Tasks 2–4): `Rensei.Hostage` and the eight deeds; four empty animation slots; DownedManager and TakedownService refuse a captor or a hostage both ways. Nothing a player can see changes.
3. **The server hold** (Tasks 5–9): `HostageService` and `Requests.Hostage`. Taking from knocked, the one Release path and every exit; the pair held for real; the grab, the struggle and the time limit; the captor menu's Release and Finish with the deeds; the human shield and rescue.
4. **Restrictions, money and the client** (Tasks 10–12): what a captor and a hostage can't do, and the travel refusals; ransom and turn-in; the prompt, the HUD, the captor wheel and touch.
5. **The close** (Tasks 13–14): Foundry parity and the full sweep; the docs and the one Changelog entry.

**Tech Stack:**
- Roblox Studio Luau, through `Art/Tools/rbxc.py`.
- Python 3.14 (stdlib only), only for `sync.py --check` and `test_sync.py`.

**Spec:** `Documents/specs/2026-10-21-hostage-design.md` (binding; approved by the owner 2026-10-25). It predates World Plan 1's roads, papers and stowaways and the assassinations work, so the **Audit** below says what is stale and rules on it (PROPOSAL). Every number in the spec and here is a **PROPOSAL** unless it quotes an owner decision.

- "Do not expose API keys, credentials, private player data, or other secrets."
- "Do not blindly copy another game's code or assets."

**PvP and PvE (owner and controller rules):**
- **Hostages are player on player only.** `Rensei.Hostage.CheckTake` refuses an NPC first (`"not_player"`), whatever else is true, and the stand-in seam refuses NPC rigs.
- **PvE stays PvE for takedowns.** No takedown path ever accepts a player. `Takedown.Check` already refuses one first (`Takedown.lua:117`); Task 4 keeps a test that proves it, stand-ins included.

**Labels and records:**
- Every invented number or name is labelled **PROPOSAL**, in code comments and docs.

- Implementers report to the controller in their final message. They never dispatch subagents and never write under `.superpowers/`.

**Scripts live in both places:**
- Edit the repo file first, then set it into **both** places:
  ```

  python -I Art/Studio/Regions/Foundry/data/sync.py --place ye|foundry --check
  ```

- `Modules`, `RenseiServer` and `Assets` are packages. Publishing them is the owner's (Task 14's checkpoint).
- **Script edits are refused while Play runs.** Stop, unhook and unlock before syncing.

**Reversible Studio scripts** (only the animation slots, Task 3) follow `Art/Studio/Takedown/anim_slots.lua`'s contract:
- `local MODE = "plan"` on its own line. The modes are `plan` (read-only), `apply`, `undo`, `check` (read-only) and `test` (only while not applied: snapshot, apply, check, undo, snapshot; both snapshots equal).
- **`apply`:**
  - refuses, changing nothing, when its flag is set, while Play runs, or while PlayLock is set (a Foundry run also checks Ye's);
  - runs in a pcall with a journal;
  - makes one ChangeHistoryService recording;
  - marks what it creates with `HostageAdd = true`.
- **`undo`** removes exactly those, and refuses for any slot whose `AnimationId` is no longer `""` (an owner upload), naming it.
- **`check`** lists failure conditions and returns `PASS n / FAIL n`. It compares against constants in the script.

**Tests:**
- **RED then GREEN.** Every new check is run once where it **must fail** (before the change, or against a control that keeps today's rule), and fails. Then it passes after.
- **A check that cannot fail is not a check.** Expected numbers are written by hand in the test, never read from `Rensei.Hostage` at check time.
- **No duplicated test logic.** Shared helpers live in `RenseiTests.HostageKit` (Task 5), which **requires** `TakedownKit` (floor, Guard, Spot, PutPlayer, PutBehind, WaitFor). Nothing is copied.
- **Every Play case runs inside `HostageKit.Guard`**, which refuses to run unless **both** `TakedownKit.SnapshotArmed()` is true **and** `DataManager.IsNoSave()` is true.
- When a check fails, fix the cause in the task that owns it (the controller rules), never by loosening the check.

**Every hostage action shares one exclusion, both ways** (lesson I2, `final-review.md:75-98`):
- A character with any of `Knocked` (as an actor), `Gripping`, `Carrying`, `TakingDown`, `Holding` or `HeldBy` can't start a grip, carry, takedown or hostage.
- A target with any of `GrippedBy`, `CarriedBy`, `TakenDownBy`, `HeldBy`, `Holding`, `Gripping`, `Carrying` or `TakingDown` can't be taken by any of them.

**One Release path** (lesson from TakedownService, `TakedownService.lua:337-425`):
- Every end of a hold goes through `HostageService`'s `Release(S, Outcome)`. It is guarded by `S.Over` and the session's identity (`ByCaptor[Captor] == S`).
- Each restore step runs in its own pcall.
- It gives back every saved state on every exit: leave, death, respawn, teleport, deep water, safe zone, time-out, struggle, rescue, menu, ransom, turn-in, error and server shutdown (`game:BindToClose`).

```lua
-- Hostage (hostages plan, 2026-10-27; spec Documents/specs/2026-10-21-hostage-design.md, owner-approved 2026-10-25):
-- the numbers, the animation slot names and the pure rules of player-on-player hostages. PvP only: CheckTake refuses
-- an NPC before anything else. HostageService (server) decides; TakedownUI / HostageUI (client) only show.
-- Every number is a PROPOSAL unless it says it was measured. No Instance is read here except through the arguments,
-- so RenseiTests.Test_Hostage checks it without a game.
local Takedown = require(script.Parent.Takedown)

local Hostage = {}

Hostage.Key = "N" -- shared with takedowns: an enemy target is a takedown, a player target a hostage (controller ruling)
-- taking
Hostage.BindTime = 1.5 -- seconds to bind a knocked player (channelled, like Grip)
Hostage.BindRange = 6 -- studs, root to root (Grip's reach, TuningConfig.Downed.GripRange)
Hostage.GrabRange = 4 -- studs behind the target (spec §2)
Hostage.Height = 3 -- studs up or down
Hostage.RangeSlack = 1.5 -- server only: lag
Hostage.AngleSlack = 10 -- server only: degrees added to Takedown.BehindAngle
Hostage.GrabStart = 0.4 -- a grab's struggle bar starts here (spec §2)
Hostage.GrabWindow = 3 -- seconds the grabbed target has to fill it
Hostage.ShoveStun = 1.0 -- the captor's stun when a grab is shoved off
Hostage.BreakStun = 1.5 -- the captor's stun when a hostage struggles free
Hostage.MinHealthShare = 0.15 -- a bound hostage keeps at least this share of max health
Hostage.MinLevel = 5 -- never a player under level 5
Hostage.MaxGap = 15 -- never a target this many levels below the captor
Hostage.Cooldown = 4 -- seconds between a captor's takes
Hostage.RefusedCooldown = 0.5
Hostage.ImmuneAfter = 5 -- grab immunity after any release (spec §4)
-- holding
Hostage.LeadSpeed = 12 -- the captor's walk while holding (Carry is 11)
Hostage.Offset = CFrame.new(0, 0, -1.5) -- the hostage's root in the captor's root space: in front, same facing
Hostage.HoldTime = 180 -- seconds
Hostage.RetakeWindow = 600 -- a re-take of the same hostage within this halves the time
Hostage.MinHoldTime = 20
-- struggle (the Block key)
Hostage.StruggleStat = "Body" -- Rensei.Stats name (Task 1 checks Stats.Order)
Hostage.StrugglePress = 0.06 -- bar per press at an even Body
Hostage.StruggleRatio = {0.5, 2} -- clamp of (1 + own Body) / (1 + captor's Body)
Hostage.StruggleDrain = 0.05 -- bar lost per second
Hostage.StruggleStamina = 4 -- stamina per press
Hostage.MaxPressesPerSecond = 8 -- counted on the server
Hostage.SendsPerSecond = 4 -- the client batches presses into at most this many messages
-- the pair held for real (lesson I1): the server's watch
Hostage.WatchTick = 0.1
Hostage.LeadMult = 1.5
Hostage.LeadSlack = 2.5 -- studs/s
Hostage.LeadWindow = 1 -- seconds: a hitch's longest counted gap
Hostage.RiseSlack = 3 -- studs the pair may rise above its last allowed point (stairs) before it is put back
Hostage.PairSlack = 1.5 -- studs the hostage's root may be from the captor's root x Offset
Hostage.TeleportBreak = 40 -- a jump further than this ends the hold ("teleport") instead of a snap back
-- shield
Hostage.ShieldArc = 70 -- degrees either side of the captor's front
-- money
Hostage.RansomMin = 50
Hostage.RansomPerLevel = 100 -- spec: 10 x level x 10
Hostage.RansomCap = 5000
Hostage.MissingShare = 0.10 -- "goes missing" (a money sink)
Hostage.RansomWait = 60
Hostage.BountyShare = 0.5 -- of a fine actually paid
Hostage.DeskRange = 12 -- studs from a State desk's root
-- safe zones (ruling R6)
Hostage.SafeTag = "RenseiSafeZone"
Hostage.StationSafeRadius = 40 -- studs from a ticket clerk or station gate (Task 1 measures)
Hostage.TrainMargin = 4 -- studs around a platform train's bounding box

-- slots (Assets.Animations.Shared.Hostage, Task 3). Empty slots play the fallback; no id is ever invented.
Hostage.Anims = {
	Bind = {Name = "Hostage_Bind", Fallback = "Gripping"},
	Hold = {Name = "Hostage_Hold", Fallback = "Carrying"},
	Held = {Name = "Hostage_Held", Fallback = "Takedown_ChokeVictim"},
	Struggle = {Name = "Hostage_Struggle", Fallback = "Takedown_ChokeVictim"},
}

Hostage.Kinds = {Bind = true, Grab = true}

local function Flat(V) return Vector3.new(V.X, 0, V.Z) end

-- the captor is in the target's rear arc: the takedowns' own rule (Takedown.Behind), never a copy
function Hostage.Behind(TargetLook, ToCaptor, Slack)
	return Takedown.Behind(TargetLook, ToCaptor, Slack)
end

-- Other is in front of the captor: within ShieldArc of its look (the shield side)
function Hostage.InFront(CaptorLook, ToOther)
	local L, D = Flat(CaptorLook), Flat(ToOther)
	if L.Magnitude < 1e-3 or D.Magnitude < 1e-3 then return false end
	return math.deg(math.acos(math.clamp(L.Unit:Dot(D.Unit), -1, 1))) <= Hostage.ShieldArc
end

-- seconds this hold may last, given how many times this hostage was taken in the last RetakeWindow
function Hostage.HoldTimeFor(Retakes)
	return math.max(Hostage.MinHoldTime, Hostage.HoldTime / 2 ^ math.max(0, Retakes or 0))
end

-- bar per press: StrugglePress x clamp((1 + Mine) / (1 + Theirs))
function Hostage.StruggleGain(Mine, Theirs)
	local R = (1 + math.max(0, tonumber(Mine) or 0)) / (1 + math.max(0, tonumber(Theirs) or 0))
	return Hostage.StrugglePress * math.clamp(R, Hostage.StruggleRatio[1], Hostage.StruggleRatio[2])
end

-- studs the captor may cover across the ground in Dt seconds
function Hostage.LeadAllowance(Dt)
	return (Hostage.LeadSpeed * Hostage.LeadMult + Hostage.LeadSlack) * math.min(math.max(Dt, 0), Hostage.LeadWindow)
end

local function Round10(X) return math.floor(X / 10 + 0.5) * 10 end

function Hostage.RansomMax(Level)
	return math.min(Hostage.RansomPerLevel * math.max(1, math.floor(tonumber(Level) or 1)), Hostage.RansomCap)
end

-- the captor's choices, lowest first: RansomMin, then a quarter, a half and all of RansomMax (rounded to 10), each
-- kept only when it is above the last and within [RansomMin, RansomMax]
function Hostage.RansomTiers(Level)
	local Max = Hostage.RansomMax(Level)
	local Out = {}
	for _, V in ipairs({Hostage.RansomMin, Round10(Max / 4), Round10(Max / 2), Max}) do
		if V >= Hostage.RansomMin and V <= Max and (#Out == 0 or V > Out[#Out]) then table.insert(Out, V) end
	end
	return Out
end

-- what the captor receives of a paid ransom
function Hostage.Net(Amount) return math.floor(Amount * (1 - Hostage.MissingShare)) end

-- the captor's bounty for a fugitive whose fine was paid (decision 8: nothing for an unpaid one)
function Hostage.Bounty(FinePaid) return math.floor(math.max(0, tonumber(FinePaid) or 0) * Hostage.BountyShare) end

-- Ctx: plain values the caller gathered. Returns true, or false and the first failing reason. The PvP rule is first.
--   IsNpc, IsPlayer, Self, Kind, Safe, InDialogue, TargetLevel, CaptorLevel, Ready, Immune, CaptorFree, TargetFree,
--   TargetKnocked, Dist, Height, Range, Behind, Clear
function Hostage.CheckTake(Ctx)
	if Ctx.IsNpc then return false, "not_player" end
	if not Ctx.IsPlayer then return false, "not_player" end
	if Ctx.Self then return false, "self" end
	if not Hostage.Kinds[Ctx.Kind] then return false, "kind" end
	if Ctx.Safe then return false, "safe" end
	if Ctx.InDialogue then return false, "dialogue" end
	if (tonumber(Ctx.TargetLevel) or 0) < Hostage.MinLevel then return false, "level_low" end
	if (tonumber(Ctx.CaptorLevel) or 0) - (tonumber(Ctx.TargetLevel) or 0) >= Hostage.MaxGap then return false, "level_gap" end
	if not Ctx.Ready then return false, "cooldown" end
	if Ctx.Immune then return false, "immune" end
	if not Ctx.CaptorFree then return false, "busy" end
	if not Ctx.TargetFree then return false, "target_busy" end
	if (Ctx.Kind == "Bind") ~= (Ctx.TargetKnocked == true) then return false, "kind" end
	if (tonumber(Ctx.Dist) or math.huge) > Ctx.Range then return false, "far" end
```

## Follow-up: journeys (ruling R5; not built here)

This is the design the follow-up plan starts from, so the work isn't lost:
- **Depart:** a held pair departs together. `Trip.Hold = {Role = "Captor" | "Hostage", With = <the other's UserId>, Nonce = <a GUID>, Left = <seconds of hold left>}` is written into each save in the same `Depart` call, before the release. The road's `Gather` takes the hostage into the captor's group for that crossing only.
- **Arrive:** `TravelService.Arrived` gives `HostageService.Resume(Player, Trip.Hold)`. It waits up to 20 s (PROPOSAL) for the other side's arrival with the same Nonce, then re-binds with `Left`. If either doesn't arrive, the hold ends and `Trip.Hold` is cleared. Arrival trusts only the save (`TravelService.lua:6-12`).
- **Train:** the stowaway route lets a pair hide in the StowZone; the ride inspection (`RideEvents.lua:127-150`) frees the hostage, fines the captor 3× the fare and raises State Heat.
- **Testing:** Studio loops Depart back to Arrive in the same place (`TravelService.lua:147-155`), so the save half can be unit-tested with stand-ins. The cross-server half needs a private live test server, which needs the owner.
